# Deploy Herbliss

Both services build from the repository root on `main`. Vercel serves the storefront and forwards `/api/*` requests to Render. The browser keeps a same-origin session cookie and sends checkout uploads through the same route. Render handles the API, database, email and WhatsApp. Local development still runs on one Next.js server.

## 1. Create the Render API

In Render, create a **Blueprint** from the GitHub repository and select `render.yaml`. It defines a Node 24 web service named `herbliss-api` and a health check at `/api/health`. The Blueprint selects the paid Starter instance so the existing Gmail SMTP integration can use ports 465 or 587. Review the plan in Render before creating the service. [Render Blueprint reference](https://render.com/docs/blueprint-spec) · [Render Free limits](https://render.com/docs/free)

| Setting                                                                                 | Value                                                                                          |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_APP_URL`                                                                   | The public Vercel storefront HTTPS origin or custom domain. Use the same origin on both hosts. |
| `MONGODB_URI`                                                                           | Atlas URI for the Herbliss database, with the production database user and password.           |
| `JWT_SECRET`                                                                            | Generated by the Blueprint. Keep it stable across deploys.                                     |
| `ENABLE_EMAIL`                                                                          | `true` when SMTP is ready.                                                                     |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_FROM`, `STORE_CONTACT_EMAIL` | Configure using the [SMTP guide](SMTP_SETUP.md).                                               |
| `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_ACCESS_TOKEN`, optional `WHATSAPP_GRAPH_VERSION`  | Configure using the [WhatsApp guide](WHATSAPP_CHECKOUT.md).                                    |

Allow the Render service’s outbound IP ranges in the Atlas project’s network access settings. Use fresh production credentials in the Render dashboard. Copy the deployed service’s HTTPS origin and check `/api/health` returns `{"status":"ok"}`. This health endpoint checks the server process. Validate Atlas access by logging in through the storefront after the next step. [Render outbound IPs](https://render.com/docs/outbound-ip-addresses)

## 2. Create the Vercel storefront

Import the same GitHub repository, use the **Next.js** preset, and leave the root directory at the repository root. Select Node.js 24.x and use a Vercel plan that permits commercial use for the live shop. [Vercel project settings](https://vercel.com/docs/project-configuration/project-settings) · [Vercel fair use guidelines](https://vercel.com/docs/limits/fair-use-guidelines)

| Setting               | Value                                                                      |
| --------------------- | -------------------------------------------------------------------------- |
| `NEXT_PUBLIC_APP_URL` | The production storefront origin, such as `https://your-store.vercel.app`. |
| `BACKEND_URL`         | The Render service origin, such as `https://your-api.onrender.com`.        |

Set both values before the Vercel build. If the storefront domain differs from the origin entered on Render, update Render’s `NEXT_PUBLIC_APP_URL` and redeploy. Authentication and checkout mutations accept the configured storefront origin. Use a separate staging backend and database to test those flows from a preview URL.

## 3. Verify from the storefront

- Open the storefront and check that the product images and videos load.
- Open `/api/health` on the storefront to verify the Vercel rewrite reaches Render.
- Create a test customer, verify the email code, open the profile, then log out and log in again.
- Submit a COD test order, then an Easypaisa test order with a fictional JPG or PNG screenshot. Verify the amounts and screenshot in the receiving WhatsApp inbox after the WhatsApp templates are approved.

The storefront currently asks search engines to skip indexing. Email signup and automatic WhatsApp delivery require their respective provider settings before customer checkout goes live.
